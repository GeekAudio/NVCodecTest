# 检测方法

这个工具主要回答两件事：驱动的安装和加载状态有没有对上，以及当前配置能不能完成指定的硬件编解码。

## 驱动怎么认

一起看已加载的核心 kext、当前进程注册的 NVMTL 编码器、磁盘组件和版本标记。缺少 `/Library/NullMoth/driver-version` 不再直接显示“未安装”。命令失败、超时与成功但没有结果分开记录。

安装版本、加载版本和插件自己的版本分别显示。辅助扩展或音频扩展不会被当作核心显卡驱动已经运行。先枚举并持有全部 Metal 设备，兼容部分 NullMoth 版本的编码器注册时机。

## 测什么

| 类别 | 项目 |
|---|---|
| 编码 | H.264 / HEVC：1080p 硬件、1080p 软件、4K 硬件，共六项 |
| 解码 | 1080p H.264 硬件与软件、HEVC 硬件，共三项 |

输入是八个完整初始化、保持不变的 NV12 8-bit 合成图案帧，循环提交。1080p 120 帧、4K 48 帧；时间戳按 30 fps；目标码率 8 / 30 Mbps；关闭 RealTime 和帧重排。

每个会话先预热八帧并排空，正式编码从关键帧开始。每项测三次，取中位 FPS 对应的完整一次结果，帧数和耗时不会混用其他轮次。使用单调时钟，计时包含提交、处理、回调和排空，不含创建会话、生成像素和预热。

要求请求、提交与有效输出帧数一致，并检查丢帧、重复、准备、回调和排空错误。解码检查输出图像和尺寸；素材可来自成功的软件编码，不依赖硬编成功。

取消只停止新提交，已提交帧会安全排空。底层驱动调用需要等它返回。整轮取消状态与每项未测试状态分开保存，已经完成的结果保留。

## 怎么确认 NVIDIA

先确认完整输出和实际 `UsingHardware…` 属性，再看归属证据：

- 实际编码器是明确的 NVMTL NVENC ID，硬件属性为 true，并完成全部帧，可确认 NullMoth/NVIDIA 编码路径。这个身份由驱动自报，详情会说明。
- 会话返回 GPU Registry ID 时，匹配 Metal 设备和 IORegistry PCI vendor-id；`0x10de` 是 NVIDIA。
- GPU ID 没返回时，保留“系统硬件 · GPU 未确认”。不能因为默认 GPU 是 NVIDIA，或进程加载了 NVDEC 库，就说这次解码用了 NVIDIA。
- 编码器身份与明确的 GPU vendor 冲突时，不确认 NVIDIA，并保留冲突原因。

软件模式明确禁用硬件。部分软件会话不提供 `UsingHardware` 属性，此时按 Apple 的禁硬件约束和属性默认语义判断，并保留属性未报告的事实。

结果使用结构化状态、归属、属性查询状态、证据和统计，不靠界面文字包含“硬件”或“NVIDIA”来判断。TXT 方便看，JSON 保留原始结构；报告使用本轮开始时采集的环境快照。

## 日志怎么用于排查

每轮环境诊断或完整测试先建立本机日志，再采集环境。测试阶段和每项结果陆续写入，取消保留部分结果；异常退出后，下次打开会把未结束记录标为中断。阶段事件合并后在独立队列写入，完整快照在每项测量结束、下一项开始前保存。脱敏规则缓存复用，每个日志任务单独管理自动释放池，减少额外负载；磁盘等待不计入该项 FPS。

日志包括系统报告机型（SMBIOS，可由黑苹果引导配置指定）、系统、CPU、内存、GPU、驱动安装与加载证据、编码器注册、会话硬件属性、GPU 查询结果、OSStatus、帧数、耗时和重复范围。反馈网页默认包含环境和测试日志摘要。`UsingHardware=true` 但 GPU 属性为空的情况会原样保留判断证据，不因提交了日志就改变归属结论。

自动留存先脱敏，最近 20 次、最长 30 天、合计最多 20 MiB；活跃会话受保护。反馈时选定一轮，检查脱敏预览，再到 GitHub 网页提交公开 Issue。超出网页 URL 预算时只预填短说明，并明确要求手动粘贴或附加完整日志。程序不自行上传、不配置 GitHub Token。

日志是诊断记录，不是系统崩溃转储，不采集视频素材、EFI 或完整系统日志。普通导出报告仍保留完整本轮环境，仅“日志与反馈”使用脱敏内容。

## 这些结果不能说明什么

合成图案不代表真实视频；同码率不等于同画质。没有做逐像素正确性、PSNR/SSIM/VMAF、功耗或长期稳定性测试。4K 短测可能不足一秒，不能拿来判断持续峰值。

测吞吐时应停止其他视频或 GPU 负载，避免同时运行多轮测试。资源忙或解码器暂时不可用会保留实际错误，不改判成“驱动未安装”。

FPS 包含第三方驱动和 VideoToolbox 的开销，不能直接横比 NVIDIA 原生 NVENCODE API 的性能表。旧版 v1.0 的缓冲和统计实现不同，也不宜混比分数。

官方 API 提供了判断依据，但本工具没有 Apple 或 NVIDIA 的跑分认证。
