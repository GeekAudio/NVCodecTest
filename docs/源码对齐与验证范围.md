# 源码对齐与验证范围

核对日期：2026-10-27。规则固定到 NullMoth `v2.6.2` / `6e375469bd02f5421a2a3d7c408507d5099e2c38`，不会把未来版本自动当成已验证版本。

## 判断依据

- [NVMTLDevice.m](https://github.com/nullmoth/nvidia-macos-driver/blob/6e375469bd02f5421a2a3d7c408507d5099e2c38/plugin/NVMTLDevice.m)：Metal 设备初始化时进行进程内注册；明确的两种 NVENC ID、NVDEC 注册、六个视频开关，以及 GPU profile 对模块的选择。
- [NVRM.cpp](https://github.com/nullmoth/nvidia-macos-driver/blob/6e375469bd02f5421a2a3d7c408507d5099e2c38/kexts/NVRM/NVRM.cpp)：PCI 节点上的 `nvrm-gpu-profile` 是驱动声明；映射上下文无效、范围不合法等情况可返回 `kIOReturnBadArgument`。仅凭一个映射错误不能进一步断定是哪条分支。
- [Apple 会话硬件解码属性](https://developer.apple.com/documentation/videotoolbox/kvtdecompressionpropertykey_usinghardwareacceleratedvideodecoder)和[GPU Registry ID](https://developer.apple.com/documentation/videotoolbox/kvtdecompressionpropertykey_usinggpuregistryid)：硬件路径与具体 GPU 身份分开判断。
- 磁盘文件按源码中的插件及视频模块路径检查是否存在，只显示存在/缺失；不读取内容、不计算组件哈希。

编码仍需完整输出、实际硬件属性、明确的 NVENC ID 或会话 GPU 的 NVIDIA PCI 身份共同成立。解码没有返回 GPU ID 时继续保留设备未报告。库文件载入、profile、注册或文件存在性都不单独代替实际会话证据。

NVIDIA 音频、USB 控制器不能作为 NVIDIA 显卡存在的证据，PCI display/3D 类与其他设备分开。Turing GTX 16 使用上游的家族前缀规则；不能因 profile 中 NVENC class 为零而判定不支持。Ada、未知家族或缺失 profile 时没有返回内置模块，不等于该硬件没有编解码能力，第三方编码器和实际会话仍要分别观察。

## 两项失败的对照

本机一轮完整测试的 H.264 / HEVC 强制硬解均在会话创建时返回 `-12913`，提交帧数为零。后续同一受控程序开启日志时捕获到：

```
nvd264: usermode map -> 0x1f
nvrm_xnu: IOConnectMapMemory64 -> 0xe00002c2
nvd265: cpu map -> 0xffff
```

`0xe00002c2` 为 IOKit `kIOReturnBadArgument`。部分轮次随后是会话创建失败，另有 HEVC 会话创建成功、预热回调 `-12909` 并丢帧的轮次；这些失败全部保留，不能混成“显卡不支持”。

两次关闭日志的短对照中四个硬件项目全部通过；开启日志的短对照均出现失败。关闭日志的同引擎完整九项也全部通过。这表明进程内日志活动会触发或放大当前驱动的用户态映射问题；尚未证明驱动内部具体哪一个状态、句柄或分支出错。

1.4.1 将 VideoToolbox 测量放在无窗口、无日志文件写入的独立进程，父进程接收结果、写脱敏日志并保留驱动 stderr。强制硬件要求和输出校验保留；没有把失败改成软件成功，也没有静默重试。新架构本机完整九项通过，仍需更多机器进行实际验证。
